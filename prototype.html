KEY FLOWS

四条关键路径

设计目标只有一个：把「手机上答 agent 一句话」的成本降到两步。

① 手机答一句

推送到达→点开→快捷作答

agent 等待输入时 daemon 推送到手机；点通知直达会话，问题选项变成可点的胶囊按钮。

对比现状 ssh → aaa → 找项目 → resume ≈ 6 步

② 无缝接力

Mac 开会话→出门→手机续

会话 = daemon 里的一个 PTY + 服务端 VT。任何设备连上都是同一现场，断线重连秒级重绘。

③ 随手开新活

＋→选 agent / 终端→秒进

与 CLI 的 New <agent> 同义：留空名称用时间戳、写入注册表、bypass 权限启动；「普通终端」是新增的第 6 个选项。

④ 项目治理

项目表→多选→删除 + purge

换 agent / 删除 / 批量操作完全复用 aaa 的注册表与 purge 语义，删前列明各 agent 会话条数。

ARCHITECTURE

架构一页图

daemon 是唯一的会话所有者；CLI 的项目扫描 / 会话查找 / AI 命名 / purge 逻辑整体移植进来。

  • 快捷键条 / 消息式输入 / 快捷作答
  • 浏览器 PWA 兜底（daemon 直接 serve）

DECISIONS

六个设计决策

01首页是会话，不是菜单。daemon 让会话常驻后，手机上最高频的动作是「看 agent 卡在哪、回一句」，菜单入口降级为 FAB 与底栏。
02等待输入是一等状态。黄点、置顶、推送、快捷作答胶囊，全链路围绕它设计；这是移动端相对 ssh 的最大增益。
03消息式输入。长 prompt 用输入框＋发送（享受语音键盘与中文输入法），短操作用快捷键条直捅 PTY，两种模式并存。
04Mac 端菜单栏优先。本机已有 iTerm，主窗口不抢戏；菜单栏图标带等待计数，点条目直达会话才是日常动线。
05语义完全对齐 CLI。注册表、resume 模板、purge、时间戳命名、SSD 挂载保护——UI 不发明新行为，只换交互皮肤。
06网络交给 overlay。不做公网暴露、不做账号体系；tailscale/easytier + 静态 token + 扫码配对，个人使用刚好够。
